# 动态调整规则

引擎输入明确包含 previous_state、previous_plan、recent_feedback、trend_data；规则实现在 adaptation.py。每次变化返回 change、reason、previous_value、new_value。调整审计保存在快照audit。

- 进阶：PROGRESS，近14天至少4次已报告训练，完成均值与覆盖均≥0.85，至少4次RPE且均值≤6，最近2天内恢复记录显示疲劳≤4、睡眠≥7小时、各部位酸痛≤4；距上次调整≥7天。confidence≥0.6时间增加5%，否则2%；每次只改时间，实际计划仍受可用时间限制。
- 疲劳≥8或任何部位酸痛≥8：进入DELOAD，基线乘0.75，一次应用，不按每天重复扣减。
- 近7天≥3天疲劳≥7且睡眠<6小时，最近3次训练完成率严格下降：进入DELOAD。
- 单次睡眠<6小时：本日分钟减少10%，不重置基线；减量阶段不叠加这一规则。未满足进阶规则时保留基线。
- 日历窗口含当天，分别7/14/30天；完成率分母仅含有实际记录的到期计划，并单列已报告/已安排覆盖率。未到期的今天计划不计入执行率。缺失不是成功也不是失败；低覆盖不能进阶。
- 体重用真实日期回归斜率，单次读数不决定计划。体重预测至少7次读数、跨14天、有活动记录和足够反馈覆盖；反向或近乎零斜率不输出日期。
- 初次confidence为0.15至0.30，基础字段和近30天四类观测覆盖将其提高，最大0.9；陈旧数据退出窗口会降低分数。它只衡量数据充足程度，不是预测正确概率。

这里的25%、5%、睡眠阈值、平台阈值与预测范围都是保守且可审计的工程默认值，没有被宣称为适用于所有人的临床结论。未来应通过真实纵向数据、教练复核和个体反应校准。

## 连续性修正

提交训练记录不使当天计划失效；恢复与档案更新可重新评估，但前次训练上下文只取严格早于当天的计划，避免把当天缓存当作前一天。天气替换保存处方并记录前后变化；重新加载保持已选择动作。安全检查始终优先于缓存。

每次进入PROGRESS（含DELOAD恢复）重新开始至少21天的平台观察窗口，只使用本轮进入后的标准化测试；既往平台证据不重复触发下一次减量。新窗口内证据仍显示平台时可再次进入PLATEAU，这不是永久豁免。
